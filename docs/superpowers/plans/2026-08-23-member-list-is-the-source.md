# 가입자 목록을 유일한 근거로 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development 또는 superpowers:executing-plans.

**Goal:** 신입 여부를 자동 생성 문구가 아니라 가입자 목록으로만 판정한다. 그리고 목록이 판정 창을 실제로 덮게 한다.

## 왜 고치는가 — 오늘 라이브에서 드러난 것

워터마크를 지우고 오늘치 111건을 리허설로 판정했더니 5건이 SKIP됐다. 관리 화면 멤버 목록과 대조한 결과는 이랬다.

| 닉네임 | 가입일 | SKIP이 맞았나 |
|---|---|---|
| 혼수상태 | 2026.08.23. | **틀림** — 오늘 가입 |
| 힌둥 | 2026.08.22. | **틀림** |
| evanston75 | 2026.08.22. | **틀림** |
| 도야2 | 2026.08.21. | **틀림** |
| 선릉너구리 | 400명 밖 (08.20 이전) | 맞음 |

다섯 건 모두 근거가 "표에 없음"으로 같았는데 넷은 틀리고 하나만 맞았다. **같은 근거가 한 번은 맞고 한 번은 틀렸다면 그것은 판단의 근거가 아니다.**

원인은 둘이다.

**표가 판정 창을 덮지 못한다.** 설계는 "표에 없음은 결론이지 미지가 아니다"(설계 문서 §5.2)를 전제하는데, 그 전제는 표가 창 전체를 담을 때만 참이다. 첫 수확이 1페이지(100명)로 끊겨 3일 창(400명 이상)을 못 덮었다.

**문구 경로가 창 검사를 건너뛴다.** 자동 생성 문구를 만나면 가입일을 보지 않고 통과시킨다. 평소에는 자동 생성 글이 곧 당일 가입이라 문제가 없지만, 워터마크를 지우거나 오래 꺼뒀다 켜면 며칠 치 자동 생성 글이 **창과 무관하게 전부 통과한다.** 이 경로가 위의 전제 붕괴를 가려서 오늘까지 드러나지 않았다.

## Global Constraints

- 코드와 주석은 **영어**, 화면 문구는 한국어이며 locale 파일에 둔다
- 커밋에 AI 서명·공동저자·이모지 금지
- 주석은 *왜*를 설명하고 계획 태스크 번호를 참조하지 않는다
- TDD: 실패하는 테스트 → 최소 구현 → 통과 → 커밋
- 죽은 코드를 남기지 않는다. 쓰이지 않게 된 함수와 그 테스트는 지운다
- 판정 창의 기준점은 **세션 실행 당일**이며 KST 달력 일수로 센다

## 바꾸는 규칙

| 상태 | 판정 |
|---|---|
| 표에 있고 창 안 | 환영 |
| 표에 있고 창 밖 | 제외 |
| 표에 없음 (표가 창을 덮음) | 제외 — 창 밖이 확정 |
| 목록을 못 읽음 | 보류 |

**감수하는 것.** 목록을 못 읽으면 자동 생성 글까지 전부 보류된다. 지금은 문구만으로도 나갔다. 근거 없이 환영하는 것보다 멈추는 편이 낫고, 보류는 다음 세션이 다시 집으므로 유실이 아니며, **멈추면 눈에 띈다** — 조용히 몇 명이 빠지는 것보다 낫다.

### Task 1: 목록이 창을 덮게 하고, 문구 경로를 없앤다

**Files:**
- Modify: `src/desktop/membership.ts`, `src/shared/automations/welcome-comment/newMember.ts`
- Modify: `src/extension/cafeClient.ts` (페이지 백스톱)

- Test: `tests/desktop/membership.test.ts`, `tests/shared/automations/welcome-comment/newMember.test.ts`, `tests/extension/cafeClient.test.ts`

**목록 수확의 바닥은 판정 창이다.** 표가 비어 있으면 `오늘 − windowDays`보다 오래된 가입일을 만날 때까지 페이지를 거슬러 읽는다. "1페이지만"은 없앤다. 표가 이미 있으면 지금처럼 아는 회원을 만날 때까지만 읽는다.

**명시적 페이지 상한을 없앤다.** 멈추는 기준은 오직 데이터다 — 창 밖 날짜를 만나거나, 목록이 끝나거나, 아는 회원에 닿으면 멈춘다. 목록은 유한하므로 루프는 반드시 끝난다.

숫자로 자르지 않는 이유는 이 계획이 고치는 문제 자체가 **조용한 잘림**이기 때문이다. 40이든 100이든 임의의 상한은 언젠가 데이터가 그 값을 넘는 날 같은 사고를 반복한다.

다만 **비정상적으로 긴 순회는 드러나야 한다.** 50페이지를 넘기면 경고 로그를 남긴다. 멈추지는 않는다 — 날짜 형식이 바뀌는 등으로 종료 조건이 깨졌을 때 그것을 알아차릴 수단이다.

글 수집의 첫 수확도 같다. 오늘 0시까지 전부 읽고 페이지 수로 자르지 않는다.

**guard는 가입일만 본다.** 자동 생성 문구 분기를 지운다. `NOT_TRACKED`는 이제 "창 밖"을 뜻하며 SKIP이다. 저장된 가입일이 형식에 맞지 않으면 지금처럼 `STRUCTURE_CHANGED` 위험 플래그다.
