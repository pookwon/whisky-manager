# 수집 현황 화면을 단계 순서로 정리하는 설계

- 작성일: 2026-10-04 (KST)
- 대상: 렌더러의 수집 현황 화면(`src/renderer/views/CollectionStatus.tsx`와 `views/collection/*`)
- 상태: 설계 확정, 구현 전

## 1. 왜 필요한가

수집 현황 화면에는 루프가 번갈아 도는 세 작업 — 목록 걷기, 검색어 보충, 빈 id 확인 — 이 각자 만들기·시작·중지 컨트롤을 들고 나란히 쌓여 있다. 세 작업은 실제로는 순서가 있는 한 흐름이다.

1. 목록을 걷는다. 게시판 목록이 카페 한계에서 끊기면 진행표에 `카페 한계`로 남는다.
2. 한계 너머 구간을 제목 검색으로 채운다(검색어 보충). 큰 게시판의 오래된 글에 닿는 유일한 길이다.
3. 검색으로도 비어 있는 글 번호를 하나씩 읽는다(빈 id 확인).
4. 빠진 글이 없는지 점검한다.

지금 화면은 이 순서를 보여 주지 않는다. ③ 카드가 ①의 기간 폼보다 위에 있고, ①에는 하나는 늘 꺼져 있는 `이어서 수집`·`중지`가 나란히 있으며, 진행 중인 작업이 있어도 새 작업 폼이 늘 펼쳐져 있다. "블록", "기준선", "id" 같은 내부 용어도 앞에 그대로 보인다.

목표는 **초보 운영자가 화면만 보고 지금 무엇을 해야 하는지 알 수 있게** 하는 것이다.

## 2. 무엇이 바뀌지 않는가

- IPC, 러너, 루프의 번갈아 돌기, 수집 DB와 마이그레이션, 확장과 프로토콜: 그대로
- 수집 설정 화면, 대시보드, 회원 수집 화면: 그대로
- 버튼이 부르는 API는 지금과 같다. 화면은 이미 받는 상태값만으로 판단한다.

렌더러만 바뀌므로 `PROTOCOL_VERSION`, 수집 마이그레이션, 확장 재설치와는 무관하다.

## 3. 화면 구성

위에서 아래로: **다음 할 일** → ① 목록 수집 → ② 검색어 보충 → ③ 빈 글 번호 확인 → ④ 점검 → 최근 실행

### 3.1 다음 할 일

화면 맨 위의 한 칸. 지금 할 일을 한 문장과 버튼 하나로 알려 준다. 아래 순서로 처음 맞는 것 하나를 고른다.

| 순위 | 조건 | 안내 | 버튼 |
|---|---|---|---|
| 1 | ①②③ 중 하나가 도는 중 | `② 검색어 보충이 돌고 있습니다. 기다리면 됩니다.` | 그 단계의 중지 |
| 2 | ① 작업이 있고 미완료 | `① 14:20에 이어서 돕니다. 기다리거나 지금 이어서 할 수 있습니다.` (예약이 없으면 `직접 눌러야 이어서 돕니다.`) | 지금 이어서 |
| 3 | ② 작업이 있고 미완료 | `② 이어서 보충할 수 있습니다.` | 이어서 보충 |
| 4 | ③ 작업이 있고 미완료 | `③ 이어서 확인할 수 있습니다.` | 이어서 확인 |
| 5 | ① 진행표에 `카페 한계` 게시판이 있고, ② 작업이 그 게시판의 것이 아님 | `137 게시판은 목록으로 더 내려갈 수 없습니다. ② 검색어 보충으로 채우세요.` | 보충 준비 |
| 6 | ② 작업이 끝났고 ③ 작업이 없음 | `③ 검색으로도 못 찾은 글을 하나씩 확인하세요.` | 빈 글 번호 목록 만들기 |
| 7 | ② 작업이 끝났고 ③ 작업도 끝났지만 ③의 기간이 ②의 기간과 다름 | `③ 빈 글 번호 확인은 이미 한 번 했습니다. 다시 만들 수는 없습니다.` | — |
| 8 | ① 작업이 없음 | `① 수집할 기간을 고르세요.` | 기간 고르기 |
| 9 | 그 밖 | `할 일이 없습니다. ④ 점검에서 빠진 글이 없는지만 보세요.` | — |

- `카페 한계` 게시판이 여럿이면 진행표 순서상 첫 게시판을 고른다.
- **보충 준비**는 ② 폼을 펼치고 그 게시판을 미리 고른 채 그 자리로 화면을 옮긴다. 작업은 만들지 않는다.
- **기간 고르기**는 ①의 새 기간 폼을 펼치고 그 자리로 옮긴다.
- 거절 문구(확장 미연결 등)는 이 칸에서 누른 경우 이 칸에 뜬다.

### 3.2 단계의 공통 틀

```
[번호] 이름                 [배지]        [주 버튼]
       이 단계가 하는 일 한 문장
       ─ 본문 ─
```

- **배지**: `할 일` / `진행 중` / `완료` / `필요 없음`. 색은 기존 tone(accent·ok·warn·idle)을 쓴다.
- **주 버튼**: 상태에 따라 하나만 보인다. 도는 중 → 중지, 미완료·대기 → 이어서, 작업 없음·완료 → 없음(본문의 폼이 그 역할).
- **누를 수 없을 때**는 버튼을 숨기거나 꺼 두기만 하지 않고 옆에 이유를 쓴다(예: `다른 수집이 도는 중입니다`).
- **필요 없음** 단계는 흐리게 접고 이유를 한 줄 붙인다. 펼쳐서 직접 쓸 수는 있다.
- **접힘**은 화면을 처음 그릴 때의 기본값일 뿐이다. 운영자가 펼치거나 접으면 폴링이 상태를 되돌리지 않는다.
- 단계가 남긴 거절·결과 문구는 그 단계 안에 뜬다.

### 3.3 단계별

**① 목록 수집** — "고른 기간의 글을 게시판 목록에서 차례로 읽어 옵니다."

| 배지 | 조건 |
|---|---|
| 진행 중 | 목록 실행이 도는 중 |
| 할 일 | 작업이 없거나 미완료 |
| 완료 | 작업이 끝남 |

- 늘 보이는 것: 대상 기간, 진행 막대와 %, 새 글·경과(도는 중) 또는 마지막 수집(쉬는 중), 활동 시간 무시 중이면 그 사실, 게시판별 진행표
- **새 기간 수집** 폼(시작·끝 날짜): 작업이 미완료면 접고, 없거나 완료면 편다. 기간 바꾸기 확인 칸은 폼 안에 그대로 둔다.
- **자세히**에 넣는 것: `읽는 목록`(게시판별/전체글, 기본 게시판별), `활동 시간 무시` 버튼(작업이 미완료일 때만)

**② 검색어 보충** — "목록으로 닿지 않는 오래된 글을 제목 검색으로 찾아 채웁니다."

| 배지 | 조건 |
|---|---|
| 진행 중 | 보충 실행이 도는 중 |
| 할 일 | 작업이 미완료, 또는 3.1의 5번 조건 |
| 완료 | 작업이 끝났고 5번 조건이 아님 |
| 필요 없음 | 작업이 없고 `카페 한계` 게시판도 없음 — `목록 끝에 닿은 게시판이 없어 필요 없습니다.` |

- 늘 보이는 것: 게시판·기간, `검색어 n / 전체 · 새 글 n건`, 이번 차례 진행(도는 중), `아직 못 거둔 글 약 n건`
- **새 보충 작업** 폼(게시판·시작일·미리 보기·만들기): 작업이 있으면 접는다. 기존 작업을 바꾸는 확인은 `window.confirm` 대신 ①의 기간 바꾸기처럼 화면 안 확인 칸으로 묻는다 — 지금 작업이 어디까지 갔고, 바꾸면 진행 위치가 사라진다는 것.
- **자세히**에 넣는 것: 검색어별 진행 표, 커버리지 계산식(빈 구간 id 수·기준선 비율)

**③ 빈 글 번호 확인** — "검색으로도 못 찾은 글을 글 번호로 하나씩 읽어 거둡니다. 읽어도 조회수는 오르지 않습니다."

| 배지 | 조건 |
|---|---|
| 진행 중 | 확인 실행이 도는 중 |
| 할 일 | 작업이 미완료, 또는 3.1의 6번 조건 |
| 완료 | 작업이 끝남. 3.1의 7번 조건이면 그 문장을 함께 보인다 |
| 필요 없음 | 작업이 없고 ② 작업이 없거나 미완료 — `② 보충이 끝나야 쓸 수 있습니다.` |

- 완료면 단계 전체를 한 줄로 접는다: `확인 완료 · 저장 1,625건`
- 늘 보이는 것(펼쳤을 때): 기간, `확인 n / 전체 · 저장 n건`, 이번 차례 진행
- **자세히**에 넣는 것: 삭제·읽기 불가·기타 내역

**④ 점검** — "모은 글의 범위와, 빠진 페이지가 없는지 보여 줍니다." 배지 없음.

- 수집한 글·게시판 통계, 수집 구간, 빠진 글 점검(지금 그대로)

**최근 실행** — 지금 그대로 8건.

### 3.4 쉬운 말

화면 앞에 보이는 문구에서:

| 지금 | 바꿈 |
|---|---|
| 블록, 이번 블록 | 이번 차례 |
| id, 빈 id | 글 번호, 빈 글 번호 |
| `빈 구간 id N개 중 비어 있는 것 M개. 기준선 r%(…)를 빼면 아직 못 거둔 글 약 K건` | 앞: `아직 못 거둔 글 약 K건` / 자세히: 원래 문장 |
| 빈 id 확인 (단계 이름) | 빈 글 번호 확인 |

로그 화면과 대시보드의 문구는 이번에 바꾸지 않는다.

## 4. 코드 구조

### 4.1 판단은 순수 함수

| 파일 | 하는 일 |
|---|---|
| `views/collection/nextStep.ts` | 수집 상태·보충 뷰·빈 id 뷰·예약을 받아 3.1의 표에서 하나를 고른다. 결과는 판별 유니온: `running(step)` / `listWaiting(nextRunAtMs)` / `searchResume` / `probeResume` / `searchNeeded(boardId, boardName)` / `probeCreate` / `probeSpent` / `pickPeriod` / `allDone` |
| `views/collection/stepStates.ts` | ①②③의 배지와 `필요 없음`일 때의 이유를 정한다(3.3의 표) |

두 함수 모두 렌더러가 이미 받는 `CollectionStatusView`·`BoardSearchStatusView`·`ArticleProbeStatusView`·`CollectionScheduleView`만 읽는다. 보충·빈 id 뷰가 `ready`가 아니면 그 단계는 없는 것으로 친다.

### 4.2 화면은 단계마다 한 파일

| 파일 | 역할 |
|---|---|
| `views/collection/CollectionStep.tsx` | 3.2의 공통 틀. 접힘은 처음 그릴 때만 기본값을 쓰는 로컬 상태 |
| `views/collection/NextStepPanel.tsx` | 3.1 |
| `views/collection/ListWalkStep.tsx` | ① 지금 `CollectionStatus`의 실행 배너·`BoardQueue`를 옮긴다 |
| `views/collection/PeriodForm.tsx` | ①의 새 기간 폼과 기간 바꾸기 확인 |
| `views/collection/BoardSearchStep.tsx` | ② `BoardSearchCard.tsx`를 바꾼 것 |
| `views/collection/BoardSearchJobForm.tsx` | ②의 새 보충 작업 폼과 화면 안 확인 |
| `views/collection/ArticleProbeStep.tsx` | ③ `ArticleProbeCard.tsx`를 바꾼 것 |
| `views/collection/CheckStep.tsx` | ④ 통계·수집 구간·`IdGapPanel` |
| `views/collection/RecentRuns.tsx` | 최근 실행 목록(`RunRow`) |

- `CollectionStatus.tsx`는 머리말, 저장소 없음 분기, 단계들을 순서대로 엮는 일만 남는다.
- "보충 준비"·"기간 고르기"가 다른 단계의 폼을 펴는 일은 `CollectionStatus`가 상태 하나(`{ form: 'period' } | { form: 'search', boardId } | null`)로 들고 내려 준다. 폼이 그 요청을 받으면 펴고 `scrollIntoView` 한다.
- `BoardSearchCard.tsx`·`ArticleProbeCard.tsx`는 새 파일로 대체되며 지운다.

### 4.3 문구

- 새 문구는 `src/shared/text.ts`의 `TEXT.collection` 아래(`steps`, `badges`, `next`)에 둔다. 값을 받는 문구는 함수로 둔다.
- `boardSearchLines.ts`·`articleProbeLines.ts`의 진행·커버리지 문장은 3.4대로 고친다.
- 쓰이지 않는 `TEXT.collection.periodHeading`은 지운다.

## 6. 범위 밖

- **③을 다시 만들 수 있게 하기.** ③ 작업은 한 번만 만들 수 있다(`articleProbeRepository.createJob`이 기존 행이 있으면 거부). 다른 게시판에 ②를 새로 끝내도 ③으로 이어지지 않는다. 화면은 3.1의 7번으로 이 사실을 알리기만 하고, 다시 만들 수 있게 바꾸는 일은 동작 변경이라 따로 다룬다.
- 단계가 끝나면 다음 단계를 저절로 만드는 일. 화면은 안내만 하고 만드는 것은 운영자가 누른다.
