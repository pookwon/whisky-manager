# 댓글 작성자를 확인해 판정한다

> 2026-08-24. [안내 댓글 없는 오늘 글 설계](2026-08-23-uncommented-greetings-design.md)의 판정 규칙은 그대로 두고, **그 규칙에 필요한 사실을 어떻게 얻는지**만 바꾼다.

## 1. 무엇이 잘못되어 있었나

규칙은 "**운영진** 안내 댓글이 없는 글"이다. 그런데 게시판 목록은 댓글 **수**만 주고 작성자를 주지 않는다. 목록 마크업을 확인해보면 댓글이 1개인 글도 `<ul class="cmlist"></ul>`가 비어 있고, 눌렀을 때 `showComment()`가 채운다.

그래서 파서는 댓글 수가 1 이상이면 "누구인지 모른다"는 뜻으로 `null`을 돌려주고, 가드는 `COMMENT_CHECK_FAILED` 위험 신호를 붙이며, 무승인 전자동은 위험 신호가 붙은 글을 건너뛴다.

결과적으로 **회원끼리 인사만 오간 글과 운영진이 이미 답한 글이 구분되지 않고 둘 다 건너뛰어진다.**

### 1.1 실측 (2026-08-24 낮)

오늘 올라온 4건이 전부 댓글을 갖고 있어 **현재 규칙의 대상은 0건**이었다. 각 글의 댓글을 실제로 조회한 결과:

| 글 | 댓글 작성자 | 판정 |
| --- | --- | --- |
| 334555 달마다바꿔요 | 애링, 네 오, 260822 | 회원만 — **대상이어야 함** |
| 334556 신신 | 네 오, 260822 | 회원만 — **대상이어야 함** |
| 334557 온더락쓰 | 260822 | 회원만 — **대상이어야 함** |
| 334558 | 카페 스텝 | 운영진 답함 — 건너뜀이 맞음 |

**4건 중 3건을 놓치고 있었다.** 조회 4건에 5.1초, 건당 평균 1.26초, 실패 0건.

## 2. 판정 근거를 실제 작성자로 바꾼다

댓글이 있는 글은 그 글의 댓글을 조회해 작성자를 얻은 뒤 판정한다. 조회는 이미 있는 `CHECK_COMMENTS`를 쓴다 — 쓰기 직전 재확인이 쓰는 그 경로다.

조회 간격은 **1~1.5초 무작위**다. 고정 간격이 아닌 이유는 페이지 순회·댓글 간격과 같다: 일정한 박자로 두드리는 트래픽은 그 자체로 눈에 띈다. 값은 `src/shared/schedule.ts`에 `nextActionDelayMs`·`nextPageFetchDelayMs`와 나란히 둔다.

## 3. `null`이 뭉치고 있는 두 뜻을 가른다

```ts
if (match === null) return null            // 댓글 수 표시를 못 읽음
return Number(match[1]) === 0 ? [] : null  // 댓글이 있음
```

앞은 **목록 구조가 바뀌었다는 신호**이고, 뒤는 **조회하면 풀리는 것**이다. 지금은 같은 값이라 구분할 수 없다.

목록 파싱 결과는 세 상태를 갖는다.

- **아무도 안 달았다** — 조회 없이 대상
- **댓글이 N개 있다** — 조회해서 작성자를 확인해야 판정 가능
- **읽지 못했다** — 조회할 근거조차 없다. 위험 신호

세 번째가 첫 번째로 오해되면 이미 답한 글에 댓글이 또 나가고, 두 번째로 오해되면 쓸데없는 조회가 나간다. 값이 갈라져 있어야 둘 다 막힌다.

## 4. 조회는 처리 직전에 하나씩 한다

세션이 시작할 때 몰아서 조회하지 않는다. 한 글을 판정하기 직전에 그 글만 조회한다.

**세션당 상한이 75건인데 하루는 150건일 수 있다.** 미리 다 조회하면 절반은 이번 세션이 손대지도 않을 글에 쓴 것이 된다. 상한에 걸려 멈추면 그 조회는 통째로 버려진다.

그리고 댓글 사이 간격이 20~60초이므로, 그 사이에 1~1.5초 조회 하나가 끼는 편이 앞뒤로 몰린 요청 뭉치보다 카페 쪽에서 자연스럽다.

## 5. 이미 답한 글은 조회하지 않는다

`claim`이 가드보다 먼저 돌고, 우리가 성공적으로 댓글을 단 글에서 `null`을 돌려준다. 그런 글은 판정에 들어오지 않으므로 조회도 하지 않는다.

정상 운영에서 조회가 붙는 것은 **새 글과 남이 답한 글**뿐이다. 가장 비싼 경우는 처리한 적 없는 하루를 메울 때로, 150건이면 약 3분이다.

## 6. 확인 패널은 즉시 보이고 좁혀간다

패널을 열면 곧바로 두 숫자를 보여준다.

- **확정** — 댓글이 없어 조회 없이 대상인 글
- **확인 필요** — 댓글이 있어 조회해야 판정되는 글

조회가 진행되면서 "확인 필요"가 줄고 "댓글을 달 대상"과 "이미 댓글이 달린 글"로 갈라진다. 운영자는 좁혀지는 도중에도 승인할 수 있다.

**승인하면 세션이 그때까지의 조회 결과를 이어받는다.** 같은 글을 두 번 조회하지 않는다. 이어받은 결과가 낡아서 생기는 위험은 없다 — 쓰기 직전 재확인이 그대로 남아 있고, 그 사이에 누가 답했다면 거기서 걸린다.

## 7. 조회가 실패하면 이번 세션은 건너뛴다

진짜 조회 실패는 `COMMENT_CHECK_FAILED`다. 다음 세션이 오늘 글을 처음부터 다시 판정하므로 **저절로 재시도된다.** 보류 장치를 따로 두지 않는다 — 그런 장치를 뒀다가 걷어낸 것이 이 프로젝트의 직전 이력이다.

## 8. 바뀌지 않는 것

- 판정 규칙 — 오늘 글, 운영진 안내 댓글 없음, 작성자별 최초 글
- 쓰기 직전 재확인
- 댓글 사이 20~60초, 세션 간격 3~5시간, 상한
- 승인 정책의 동작
- 프로토콜 — `CHECK_COMMENTS`는 이미 있다

## 9. 테스트

- 댓글이 없는 글은 조회하지 않고 대상이 된다
- 댓글이 있는 글은 조회를 거쳐 판정된다
- 운영진이 답한 글은 건너뛴다
- 회원만 답한 글은 대상이 된다
- 목록을 읽지 못한 글은 조회하지 않고 위험 신호가 붙는다
- 조회가 실패하면 위험 신호가 붙는다
- 상한에 걸려 처리하지 않을 글은 조회하지도 않는다
- 조회 사이 간격이 1~1.5초 범위에서 뽑힌다 (테스트는 실제로 기다리지 않는다)
- 패널이 조회 전에 확정·확인 필요를 보여주고, 조회가 끝나면 대상·이미 달림으로 갈라진다
- 승인한 세션이 패널의 조회 결과를 다시 조회하지 않는다
